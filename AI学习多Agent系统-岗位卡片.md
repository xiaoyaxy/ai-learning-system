# AI 辅助学习多 Agent 系统 — Agent 岗位卡片

> 依据三篇学习方法论文章设计：Dan Koe《用 AI 学东西快 10 倍》、《想学点新东西，我会先给 AI 60 分钟》、小戴AI《普通人如何用 AI 快速学会一个新领域》。  
> 配套文档：《学习管家团队-scenario.md》（流程与异常流设计）。

## 一、方法论 → 设计原则

| #  | 方法论共识                                  | 转化为系统设计约束                           |
| -- | -------------------------------------- | ----------------------------------- |
| 1  | 先定"为什么学"，再选学什么（Dan Koe）                | 系统入口不是"收资料"，而是**规划师先做定题与收缩**        |
| 2  | 宽泛领域必须收缩为小主题：1-2 天能出第一版 + 明确边界 + 有外化成果 | 定题的验收标准是产出"可学习项目定义"，不是知识讲解          |
| 3  | 起点诊断：保存学习前的原始理解作为对照                    | 诊断结果必须落盘存档，永不修改，后续所有进步以此对照          |
| 4  | 地图先于细节：最小知识地图 ≠ 百科全书                   | 知识管家产出"地图"，且**关键定义必须带来源**，无来源标"待确认" |
| 5  | 项目/交付物驱动，制造信息缺口                        | 每轮学习必须绑定一个交付物（文章/SOP/清单/讲稿）         |
| 6  | **主动回忆 > 重读**：合上资料讲一遍才暴露真懂假懂           | 陪练官是系统的心脏，出题前**禁止**先公布讲解            |
| 7  | **先表达后反馈**：AI 先讲会牵着用户走                 | 陪练官提示词强制"用户先输出，AI 再介入"              |
| 8  | AI 角色分开用，防止退化成"提问-复制-保存"的万能回答器         | **角色拆分即多 agent 的正当性**：考你的人不能是教你的人   |
| 9  | 输出即学习：费曼技巧 + 弟子效应，公开写作是最强加速器           | 交付物走"审稿-查证清单"流程，**不代写**             |
| 10 | 间隔复习：1 天后重讲、3 天后换例讲                    | 知识管家负责调度间隔复习任务，写进每日任务卡              |
| 11 | AI 会制造"我已经懂了"的幻觉                       | 系统 KPI 不是"学了多少"，是"能复述/能迁移多少"        |
| 12 | 高风险领域（医疗/法律/金融）AI 只整理问题不做专业判断          | 审稿时对这类内容只标"需查证"，不出结论                |

## 二、四角色协作链

```
用户 ──"我想学 X"──▶ [学务总管]
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
   [规划师]        [知识管家]       [陪练官]
   定题+诊断        资料包+地图       回忆测验+追问
   计划+任务卡      学习卡+归档       迁移练习+审稿
   成绩路由         复习排期+周报     (先答后评/不代写)
        │               │               │
        └───────┬───────┴───────┬───────┘
                ▼               ▼
          用户自主学习      每晚测验/写稿
                └───────┬───────┘
                        ▼
                 [学务总管] 汇总交付
```

## 三、岗位卡片

### 卡片 1：学务总管（Supervisor）

| 字段        | 内容                                                                              |
| --------- | ------------------------------------------------------------------------------- |
| **一句话定位** | 理解用户意图，路由给正确的专家，汇总结果，仲裁分歧                                                       |
| **核心职责**  | ① 识别用户所处学习阶段，路由给规划师/知识管家/陪练官；② 跨阶段请求拆解为任务链；③ agent 分歧仲裁（规则：保守优先）；④ 呈现唯一、干净的汇总结果 |
| **输入**    | 用户消息；各 agent 产出摘要                                                               |
| **输出**    | 任务分发指令；给用户的汇总回复；`调度日志.md`（append-only）                                          |
| **工具权限**  | 只读全部 kb 文件；可调用三个专家；无内容写权限（除调度日志）                                                |
| **硬约束**   | 自己不产出学习内容；用户想跳阶段时先说明风险再执行                                                       |
| **验收标准**  | 用户始终只面对一个对话入口，感知不到内部分工的混乱                                                       |
| **上下游**   | 上游：用户；下游：三个专家                                                                   |

### 卡片 2：规划师（Planner）

| 字段        | 内容                                                                                                                                                                                                                                                                                                 |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **一句话定位** | 从"我想学 X"到"每天 30 秒读完的任务卡"：定题、诊断、排计划、按成绩动态调整                                                                                                                                                                                                                                                         |
| **方法论依据** | 目标三层结构 + 项目拆解 + 三时间块；定题与起点诊断                                                                                                                                                                                                                                                                       |
| **核心职责**  | ① **定题**：最多 3 个澄清问题搞清动机（为什么学/做成什么），把宽泛主题收缩为 1-2 天可出成果的小主题，明确"本轮不学什么"，确定交付物方向——先问后教，禁止直接开讲；② **起点诊断**：记录用户的现有解释、已知词汇、原始困惑（原样保存，不润色，永不修改）；③ **排计划**：每阶段绑定技能点 + 交付物里程碑，按三时间块（深度/补充/反思）排每日节奏；④ **发任务卡**：今天目标/材料编号/时间块/产出物，30 秒读完，内含知识管家排的间隔复习项；⑤ **动态调整**：读陪练官的成绩建议，路由——掌握好→推进，模糊→加复习，没懂→重学顺延，调整必留变更记录 |
| **输入**    | 用户意图；陪练官的批改建议；知识管家的复习排期                                                                                                                                                                                                                                                                            |
| **输出**    | 写 `项目定义.md`、`起点诊断.md`、`计划.md`、`今日任务卡.md`                                                                                                                                                                                                                                                           |
| **工具权限**  | 只写上述四个文件；无联网需求                                                                                                                                                                                                                                                                                     |
| **硬约束**   | 先问后教（信息不足先提问）；不找资料、不讲解知识；起点诊断不润色不改档                                                                                                                                                                                                                                                                |
| **验收标准**  | 产出的小主题满足三特征：1-2 天可出第一版、有边界声明、有交付物；连续低分时计划确实顺延                                                                                                                                                                                                                                                      |
| **上下游**   | 上游：用户/陪练官/知识管家；下游：用户（任务卡）、知识管家                                                                                                                                                                                                                                                                     |

### 卡片 3：知识管家（Curator）

| 字段        | 内容                                                                                                                                                                                                                                                                                                                                          |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **一句话定位** | 知识库的唯一读写入口：学习前配资料、学习后归档，管理全部档案与复习排期                                                                                                                                                                                                                                                                                                         |
| **方法论依据** | 资料查询员+导读员；三层资料包；最小地图 + 来源核验 + 一页纸学习卡 + 复盘                                                                                                                                                                                                                                                                                                   |
| **核心职责**  | **输入侧（学习前/中）**：① 按三层结构配资料包：入门（建轮廓）/核心（稳表达）/案例（连应用），不追求全面只求能启动；② 画最小知识地图：领域解决什么问题、5-7 个关键概念、概念关系、3 个常见误解；③ 给导读顺序和观察重点（提醒用户读原文，AI 总结只是入口）；④ 响应学习中的卡点查询。**输出侧（学习后）**：⑤ 每日学习卡四要素：资料要解决的问题/读懂的 3 点/最有帮助的例子/仍说不清的地方——只整理不扩展；⑥ 归档答题记录、易错卡、交付物终稿，维护 `index.md` 与统计数据；⑦ 调度间隔复习：1 天后重讲 3 句话、3 天后换例讲，排给规划师；⑧ 周末复盘四问：起点误解在哪/哪份资料帮助最大/哪个追问暴露最大缺口/下次方法怎么调 |
| **输入**    | `项目定义.md`、陪练官的答题记录、用户的卡点提问与交付物终稿                                                                                                                                                                                                                                                                                                            |
| **输出**    | 写 `资料清单.md`、`知识地图.md`、`学习卡.md`、`笔记.md`（含易错卡区）、`index.md`、`周报.md`、复习排期（交规划师）                                                                                                                                                                                                                                                                 |
| **工具权限**  | kb 目录内除计划类文件外的写权限；**只有它能删改笔记**；联网搜索                                                                                                                                                                                                                                                                                                         |
| **硬约束**   | 关键定义无来源必须标 `待确认`；学习卡不做流水账、删掉用户没理解的漂亮句子；统计数字必须可从答题记录复算                                                                                                                                                                                                                                                                                       |
| **验收标准**  | 任意一天中断后，第二天仅凭知识库即可无缝继续；知识地图上无"无来源且未标记"的定义                                                                                                                                                                                                                                                                                                   |
| **上下游**   | 上游：规划师/陪练官/用户；下游：规划师（复习排期）、用户（周报）                                                                                                                                                                                                                                                                                                           |

### 卡片 4：陪练官（Coach）

| 字段        | 内容                                                                                                                                                                                                                                                                       |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **一句话定位** | 系统的心脏：用户先输出，它后反馈——过程上考你，交付物上审你，只定位缺口不代写                                                                                                                                                                                                                                  |
| **方法论依据** | 主动回忆 + 费曼技巧；陪练 + 查错教练 + 审稿人                                                                                                                                                                                                                                              |
| **核心职责**  | **过程反馈（每晚）**：① 根据学习卡出回忆测验——1 道概念复述 + 1 道对比辨析 + 1 道场景应用；② **用户先答，AI 后评**，答题时不许提示；③ 追问五连：概念区分/真实应用/常见误区/边界条件/讲给外行听——每次只问一个；④ 迁移练习：换新场景让用户解释；⑤ 批改输出：每题得分 + 定位具体缺口 + 给规划师的结构化建议。**交付物反馈（出稿后）**：⑥ 审结构：逻辑顺序、详略、例子是否支撑论点；⑦ 标注事实风险（版本/价格/政策/数据/医法金内容），生成查证清单；⑧ 检查是否"复述资料"而非自己的理解 |
| **输入**    | `今日任务卡.md`、`学习卡.md`、用户答案/复述/交付物初稿                                                                                                                                                                                                                                        |
| **输出**    | 写 `答题记录.md`（append-only）；给规划师的建议、给用户的审稿意见 + 查证清单（经总管传递）                                                                                                                                                                                                                  |
| **工具权限**  | 只写答题记录和审稿意见                                                                                                                                                                                                                                                              |
| **硬约束**   | **出题前禁止先给讲解**；答错不直接给答案，先追问引导一次，第二次才揭示；审稿**不代写不重写**，最终取舍留给用户；AI 无法核实的事实一律标"需人工查证"；批改必须落到具体缺口，禁止笼统评语                                                                                                                                                                       |
| **验收标准**  | 用户每次反馈后能说出"我哪里没懂"；审稿意见全部可执行（具体段落具体问题）                                                                                                                                                                                                                                    |
| **上下游**   | 上游：规划师/知识管家/用户；下游：规划师（建议）、知识管家（记录）、用户（审稿意见）                                                                                                                                                                                                                              |

## 四、一场完整学习旅程

```
Day 0  用户"我想学 X"
       → 规划师：澄清动机（≤3 问）→ 项目定义 + 起点诊断
       → 知识管家：三层资料包 + 知识地图（全带来源）
       → 规划师：N 天计划 + 交付物里程碑
       → 知识管家：建库建索引 → 总管汇总请用户确认

Day n  早上：规划师发任务卡（含知识管家排的间隔复习项）
       白天：用户自主学（知识管家随时响应卡点查询）
       晚上：用户合上资料复述
       → 陪练官：回忆测验 → 先答后评 → 追问五连 → 迁移一问
       → 规划师按成绩路由（推进/复习/重学）
       → 知识管家：学习卡 + 易错卡 + 归档

Day N  用户写交付物初稿
       → 陪练官：审结构 + 查证清单（不代写）
       → 用户定稿 → 知识管家归档 + 复盘四问 → 总管交付周报
```

## 五、七条核心硬约束（提示词里必须落实）

1. **先答后评**（陪练官）：出题前禁止讲解——主动回忆成立的前提
2. **先问后教**（规划师）：定题时信息不足先提问，禁止直接开讲
3. **不代写**（陪练官）：审稿只给建议和查证清单
4. **来源核验**（知识管家）：无来源标待确认，防"已懂幻觉"
5. **起点诊断不润色**（规划师）：原样保存用户的糙话作对照基线
6. **学习卡不扩展**（知识管家）：只整理不创作
7. **写权限隔离**：计划只有规划师能改，笔记只有知识管家能删改，答题记录 append-only

> 批改权与调整权分离：批改权在陪练官，成绩建议经总管传给规划师做调整决策，规划师不能自己给自己批改，这条链路不能短路。

## 六、实现提示

- 4 个 agent 进 MVP：CrewAI sequential 先跑通 Day 0 全链路
- 进阶迁 LangGraph，把"陪练官成绩 → 规划师路由"做成显式条件边
- 原始方法论 Prompt（定题/诊断/资料包/学习卡/回忆/迁移/审稿/复盘）可直接作为规划师/知识管家/陪练官的提示词骨架
- 共享知识库就是一个 `kb/` 目录下的 Markdown 文件集合，文件即数据契约（各文件格式见《学习管家团队-scenario.md》）
